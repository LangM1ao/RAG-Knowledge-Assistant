# 通用RAG检索：零基础操作与排查

先理解三个问题：找到了哪份文件？找到了哪个事实？这个事实有没有进入模型真正读到的context？它们不能互相替代。

## 用一个普通技术文档理解

公司同一份报告有“数据库性能优化”和“销量预测”两个子项目。第一项写索引与EXPLAIN，第二项写时间序列。中文问数据库技术时，即使两项metadata都有同一公司名，销量预测也不能靠公司名获得关键词相关性。BM25现在只看原正文；Vector用语义跨语言寻找英文依据；RRF把有效的排名合起来。公司名来自人工明确登记，不自动猜中英文对应关系。

RRF每路每块最多一票：排名1贡献1/61，排名2贡献1/62。两路都真实相关时可以两票；不能用同一query变体重复投票。BM25分数和向量距离不是同一单位，不能直接相加。

距离0.20比0.60更相似。界面0.60表示最大允许cosine distance，超过就过滤；它不是60%正确率。BM25不使用这个向量距离。TopK是最后主召回数，候选池8是内部待排序的数量；邻块在明确多事实问题下另有总数量和字符预算。

## 日常测试步骤

1. 上传不同主题TXT或可提取文本PDF，确认列表为indexed。扫描图片PDF不属于当前能力。
2. 需要中文简称/英文标准名时，在文档别名设置中明确登记。改实体标准名后点“重建文档”，让Embedding也更新；单纯保存别名不能保证旧向量立即含新身份。
3. 选择确定的文档范围，固定TopK和0.60距离，依次运行Vector、BM25、Hybrid。不要同时改多个参数。
4. 分别用中文、英文、混合提问；再问没有记录的事实。没有词项对应的中英问题，BM25空结果合理；重点看Hybrid是否保住Vector的真实证据。
5. 查引用正文：答案每个主要事实应来自那一块、那一项目、那一文档。只有引用编号不够。
6. 新历史会显示当时模式、参数、校验状态；旧历史没有状态就是未知，不是FAIL或PASS。

## 失败时依次看什么

在受信任开发环境设置RETRIEVAL_DEBUG_ENABLED=true，并在请求debug=true。两项同时开启才返回内部诊断；正常使用保持关闭。历史trace读取还要include_debug=true。不要向陌生用户开放开发端口。

先看original_query、retrieval_query、content_query和effective_filter，确认未误改问题或范围。再看vector_filter_details的阈值前候选/距离/过滤原因；BM25看实际匹配词、正文匹配、编号约束和空原因；看fusion_ranking、最终TopK、邻块的structure_id和generation_context_chunks。最后看生成、引用和verification分别在哪一步结束。

- 相关块在阈值前也不存在：查解析、入库、query和Embedding。
- 块存在但被阈值过滤：核对真实距离、标准名后是否重建；不要立刻降低阈值。
- Vector有而Hybrid没有：核对BM25匹配的是正文还是弱词，以及RRF截断。
- 召回有而context缺失：查预算、边界或去重。
- context确实无事实而回答断言：应被同context校验拒绝。
- context有而纯拒答：区分模型生成拒答和校验FAIL，不能统称检索失败。

## 如何验证答案校验有效

“相似度阈值”“请求检索诊断”都不是答案校验本身。校验发生在生成之后，用同一个context检查实际答案，不额外检索。可靠的机制测试要固定context并控制生成答案：真实事实应PASS；故意改数字/公司/项目应FAIL并替换安全输出；校验超时或格式错应ERROR，不放行；固定纯拒答可SKIPPED；拒答后夹带编造不能跳过。

这些已有自动化用例在tests/test_answer_verification.py（以目录实际文件名为准）及相关回归中，完整生产校验代码也收录在配套源码导读。用户自然提问只能观察最终状态，不能保证每次主动触发错误答案，因此不能只靠“问一次看PASS”证明拦截有效。本轮没有削弱或重写校验器。

## 复现本轮通用评估

在项目目录使用现有虚拟环境运行python -m evals.run_general_retrieval --stage after --with-answers --run-id my_run。已有run-id拒绝覆盖，重测换新ID。此命令用非私人合成语料、新建隔离SQLite/Chroma，并真实调用现有Embedding/生成/校验API，可能产生费用。只跑检索可省略--with-answers；缓存命中不等于新的真实API请求。

完整最终代码在general_retrieval_code_walkthrough.md，每个非空行附中文导读；代码按原文件路径保存，不要把多个模块合在一个文件。指标、失败样本、历史保存审计见本轮总结和change_history.md。
