## 3. 当前真实流程

入库：原文件 → TXT/PDF实际页面解析 → 原文结构识别及有限分块 → 章节/登记身份只丰富Embedding输入 → Chroma保存原文与结构metadata；SQLite保存文档/别名。

提问：原问题 → Unicode规范化和显式别名解析 → 保守有效范围 → Vector语义query / BM25正文内容query → 有效候选过滤 → RRF（Hybrid模式）→ TopK → 同可靠叶的有界邻块 → 上下文预算 → LLM按证据生成 → 引用编号合法性 → 原有同context答案校验 → 只返回实际引用来源 → 历史保存真实参数和结果。

没有候选/上下文直接拒答，固定纯拒答可以跳过校验；FAIL、校验服务错误不会放行。PASS说明答案断言受当次context支持，不等于检索召回完整、不等于所有问题都回答了。相似度开关属于检索过滤，不是答案校验开关。

## 5. 本次实际遇到的挑战（区分来源）

1. 【用户亲测】同一项目，中文描述拒答而英文标题可答。不要把两次不同表述当成完全等价输入；追踪阈值前向量、词法候选和融合截断才确认底层污染。
2. 【Codex复现】只看来源Hit会误判进步：同文件错误章节也算Hit。增加明确证据召回和上下文召回，保留BM25负结果。
3. 【Codex真实QA】未知编号问密码却引用access背景，校验PASS。校验忠实度不等于答案相关性；修检索/生成，不放宽校验。
4. 【Codex容器验收】保存新实体后未重建向量，另一合成人物的成绩距离0.670被0.60过滤。没有用降低阈值解决；按照已存在界面说明重建后距离0.590，回答88/100且PASS。初验报告保留；最后完整流程27/27。
5. 【持久化】先备份完整Docker数据再迁移metadata和重建；真实库只有已授权的单文档。批量其他文档重建曾被自动审批拒绝，因此核实清单并仅重建确切授权ID；没有扩大私有数据外发范围。
6. 【历史纠错】原PDF写Overall GPA:75 / 100；早前字面搜索漏空格不能证明无成绩。此条是上一阶段已更正的事实，不能写成本轮新发现，也不能把GPA改称最终毕业均分。
