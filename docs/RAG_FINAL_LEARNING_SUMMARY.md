# RAG Final：用户认证、文档权限与检索隔离

## 为什么企业RAG需要权限

原来的RAG能从知识库找答案，但默认所有资料都能参与检索。人事资料和机器人手册面向的人不同，只加登录页，Bob仍可能检索Alice的私人文档。

登录像检查工牌，确定是谁；授权像门禁，决定能进哪个房间。RBAC用admin/user区分管理能力；owner_id记录谁上传；private/shared决定其他普通用户能否读取。

## SQLite与JWT各做什么

SQLite users保存用户名、角色、启用状态、密码哈希，不保存明文密码。documents保存owner_id和visibility。新上传默认private，后端从当前认证用户取得owner_id，伪造前端字段不会改变归属。

JWT是后端签名的临时通行证。校验签名和过期之后，还要查SQLite会话是否撤销、账号是否禁用。这样退出、重置密码和禁用账号才能立即影响后续请求。

## 为什么Vector和BM25都要过滤

Hybrid同时走Vector和BM25。只过滤Vector，BM25仍可能把私人片段交给RRF和LLM。正确做法是先查授权文档ID，再让两路只处理这些文档。空授权集合直接返回空，不能误当“不限制”。引用、别名、邻块、历史也继承同一权限。

## 本次实际问题

1. 空列表在旧代码中会被真假判断省略，导致全库检索。明确区分None和空列表，覆盖三模式测试。
2. 旧历史没有用户和生成范围，保留原记录但不通过新接口展示。
3. 重建失败回滚会恢复旧共享状态，已从内容回滚中排除权限字段，并复现后修复。
4. 请求排队时身份可能已被撤销，取得操作锁后重新查会话。
5. 上传大小检查放在解析之后太晚，改为接收层计数，未登录上传不读正文。
6. Docker命名卷和本地旧库是不同数据，分别备份、核对ID和原文件，不能混为一谈。
7. 首轮真实测试将虚构代号写成“禁止分享的机密密码”，模型因此拒答。保留失败记录，改成明确虚构的项目代号；算法与权限规则未为测试特殊修改。

## 如何验证

实际登录admin/Alice/Bob并直接调用API，测试未登录、非法ID、私文档隔离、共享可读不可改、撤共享历史隐藏。真实临时Chroma分别运行Vector/BM25/Hybrid，检查候选、文件名、引用和发送给LLM的上下文。再运行原有中英文与答案校验回归。

自动化测试使用固定向量和Mock LLM，方便稳定复现；另有隔离容器的真实OpenAI合成演示。实际通过数量和限制以final_security_test_report.md为准。

## 面试复述

“我最初做的是能检索和回答的RAG。考虑企业场景后，发现登录本身不能保证资料安全，所以用SQLite记录用户、文档归属和共享状态，在FastAPI后端统一检查。关键是先确定授权文档，再同时限制Chroma和BM25候选，防止Hybrid另一条分支绕过权限。我还处理了退出撤销、共享撤回后的历史、空范围和并发撤权，用真实API和临时Chroma验证数据不会串用，原来的中英文检索和答案校验也保留回归。”

这是单机单worker的工程化演示，不宣称完整企业IAM或高并发SaaS。用户此前Week8–12学习记录和检索优化总结不被覆盖。
